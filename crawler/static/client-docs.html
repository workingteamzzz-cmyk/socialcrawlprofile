Media monitoring · client API

Read your news and social media data

Your organisation received a client key (it starts with wtc_). It gives your systems read access to the articles and posts collected for you — nothing else. No account or sign-in is needed. Keep the key secret, like a password; ask for a new one if it may have leaked.

Authentication

Send the key with every request, in one of these headers:

X-Client-Key: wtc_your_key
Authorization: Bearer wtc_your_key

All endpoints are GET, answer JSON and are on the address you were given (below: https://app.example). Calls from a browser are allowed (CORS) unless your key is limited to certain websites.

Endpoints

PathReturns
/api/client/meWhat your key gives: query or topic, news / social media, data from, expiry, requests per minute.
/api/client/articlesNews articles: title, link, media, publication date and time, image, summary, sentiment, arrival time.
/api/client/articles/one?key=…One article in full: paragraphs, author, spokespersons, people mentioned.
/api/client/postsSocial media posts and comments (if your key includes them): platform, username, link, date, time, text, sentiment, emotion, likes, replies, shares, views, followers.

Parameters (articles and posts)

NameMeaning
qNarrow your data further: words, "exact phrase", AND, OR, NOT, ( ), prefix*.
start, endPublished from / to: 2026-11-20 or 2026-11-20 06:00 (Western Indonesia Time, UTC+7).
last_hoursPublished in the last N hours, e.g. 6 or 48 (instead of start).
received_sinceEverything that reached the server after this moment — fresh items and older ones that arrived late. Pass the server_time of your previous answer.
sentimentpositive, negative or neutral.
platformPosts only: instagram, tiktok, x, youtube, threads, facebook.
sortnewest (default), oldest, or received (newest arrival first).
page, sizeUp to 100 per page; the answer says how many pages there are.

Recommended schedule

Every hour?received_since=<server_time>

Everything new since your last call, late arrivals included.

Every 6 hours?last_hours=6

A safety net for the last 6 hours.

Once a day?last_hours=48

Catches articles that were published earlier and arrived late.

Every item has a fixed key. Store by key (insert or update): an item fetched twice is then never doubled.

Examples

curl

curl -H "X-Client-Key: wtc_your_key" "BASE/api/client/articles?last_hours=6&size=100"

Python — hourly job

import requests

BASE, KEY = "BASE", "wtc_your_key"
H = {"X-Client-Key": KEY}

def pull(since):
    page, items = 1, []
    while True:
        r = requests.get(f"{BASE}/api/client/articles", headers=H, timeout=60,
                         params={"received_since": since, "size": 100, "page": page}).json()
        items += r["rows"]
        if page >= r["pages"]:
            return items, r["server_time"]          # keep server_time for the next run
        page += 1

JavaScript

const r = await fetch("BASE/api/client/posts?platform=tiktok&last_hours=24", {
  headers: {"X-Client-Key": "wtc_your_key"}
}).then(r => r.json());

Answers and errors

StatusMeaning
200 {"ok": true, …}The data. total, matching, pages, sentiment shares, server_time, rows.
200 {"ok": false, "error"}A parameter could not be read (e.g. a date format) — the error says which.
401Missing, wrong, paused or expired key.
403Your key does not include this (e.g. social media), or this website may not use it.
429Too many requests per minute — wait a minute. Too many wrong keys also block the address for a while.
